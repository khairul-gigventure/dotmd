# DotMD Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build DotMD, an Arc/Chromium extension that turns the article in the current tab into a clean Markdown file (Copy or Download), and publish it as a GitHub repo.

**Architecture:** A popup injects vendored Readability.js + Turndown (+ GFM plugin) and our own `src/convert.js` + `extract.js` into the active tab. `extract.js` extracts the article, converts to Markdown, prepends frontmatter, and returns the result to the popup. All logic that matters lives in pure, Node-testable functions; the popup is a thin shell.

**Tech Stack:** Chrome Extension Manifest V3, vanilla JS (no build step for the extension), `@mozilla/readability`, `turndown`, `turndown-plugin-gfm` (vendored into `lib/`), Node `node:test` + `jsdom` for tests (dev only).

**Spec:** `docs/superpowers/specs/2026-10-04-dotmd-design.md`

## Global Constraints

- Manifest V3; permissions exactly `activeTab`, `scripting`, `clipboardWrite`. No host permissions, no network requests by the extension.
- No build step for the extension: `lib/*.js` are committed vendored files.
- Frontmatter keys, in order: `title`, `author`, `source`, `clipped` (`YYYY-MM-DD`). Missing fields are omitted, never written as `undefined`/empty.
- Body starts with `# <title>`. Images stay as `![alt](absolute-url)`; no image download.
- Filename: slug of title + `.md`, fallback `article.md`.
- Popup strings: `Copied ✓` after copy; `Tak jumpa article di page ni` when no article; `Page ni tak boleh diakses` when injection is not allowed.
- Supported elements: heading, paragraph, list, blockquote, code block, table, link, image, bold/italic.
- Never commit or push without the user's confirmation (user's standing rule); GitHub repo visibility is asked, default private.

## Review Focus

- Title/author containing YAML-special characters (`: `, ` #`, quotes, leading `-`/`[`) must still give valid frontmatter.
- Title that is non-ASCII only, emoji only, or symbols only → slug falls back to `article`.
- Relative image/link URLs in the source page → must come out absolute.
- Page with no real article (homepage, empty SPA shell) → `ok:false`, never an empty/garbage `.md`.
- `<pre><code class="language-x">` keeps whitespace and fence language; table without `<thead>` still renders as a Markdown table.

### Task 1: Project scaffold + `src/convert.js`

**Files:**
- Create: `package.json`, `.gitignore`, `src/convert.js`, `tests/convert.test.js`

**Interfaces:**
- Produces (exported via `module.exports` in Node and `globalThis.DotMD` in browser):
  - `slugify(title: string): string` — lowercase, non-alphanumerics → `-`, trimmed, max 80 chars; returns `"article"` if empty.
  - `buildFrontmatter(meta: {title?: string, author?: string, source?: string, clipped?: string}): string` — `---\n...\n---` block; a value is emitted `JSON.stringify`-quoted when it matches `/(^[\s\-?:,\[\]{}#&*!|>'"%@`])|(: )|( #)|\n|\s$/`, otherwise plain.
  - `buildMarkdown(meta, body: string): string` — frontmatter + blank line + `# title` + blank line + body, ending in a single `\n`.
  - `todayISO(now: Date): string` — `YYYY-MM-DD` (local date).
